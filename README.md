# InvoiceMailAssistant

开票邮件助手是一款面向 Windows 的本地桌面工具，用于自动读取腾讯企业邮箱中的指定开票申请邮件，提取业务字段，并将数据安全写入现有 Excel 开票登记表。

当前同时处理中外运电子签章系统和云天化电子签服务平台发送的开票申请邮件；两类邮件共用同一个 IMAP 收件箱时会在同一次检查中被分类、统计和写入对应工作表。

> 当前版本仍处于实际环境验证阶段，不建议在未经测试的情况下直接用于长期无人值守生产运行。

## 功能

### 邮件自动识别

程序通过 IMAP 只读方式访问腾讯企业邮箱。

当前目标邮件规则：

- 发件人必须标准化后等于 `sino-esign@sinotrans.com`
- 主题必须以 `中外运向您提交了开票申请` 开头
- 或者发件人必须标准化后等于 `cs@qsign.cn`，正文包含 `云天化电子签服务平台向您提交了开票申请`

每封邮件必须只有一个发件地址；来源分类完成后，处理记录、概览统计和系统托盘通知都会保留“中外运”或“云天化”来源。抓取失败但发件人仍可确认的邮件也会按来源保存为失败记录，无法确认来源的邮件不会被写入业务队列。

识别不依赖邮件是否已读，因此不会主动改变原邮箱中的已读/未读状态。

支持解析公司名称、统一社会信用代码、申请金额、申请时间、开票方式、收件人、联系电话、寄送地址、邮箱和开票备注。正文解析兼容普通文本、HTML、中英文冒号以及 `mailto:` 邮箱格式。解析失败或抓取失败的目标邮件会进入本地记录，避免静默丢失。

## Excel 自动录入

程序通过 ClosedXML 和受保护的工作表 XML 局部更新写入已有的开票登记表。默认工作表名称为 `中外运`，云天化默认使用同一工作簿中的 `云天化` 工作表；设置页可以分别调整两个工作表名称。

中外运工作表的列布局为：

| 列 | 内容 | 处理方式 |
|---|---|---|
| A | 日期 | 自动填写 |
| B | 企业名称 | 自动填写 |
| C | 信用代码 | 自动填写 |
| D | 开票金额 | 自动填写 |
| E | 到账时间 | 人工维护 |
| F | 邮箱 | 自动填写 |
| G | 是否开票 | 人工维护 |
| H | 发票是否已发送 | 人工维护 |

云天化工作表的列布局为：

| 列 | 内容 | 处理方式 |
|---|---|---|
| A | 序号 | 自动递增 |
| B | 日期 | 自动填写 |
| C | 企业名称 | 自动填写 |
| D | 信用代码 | 自动填写 |
| E | 开票金额 | 自动填写 |
| F | 到帐时间 | 人工维护 |
| G | 邮箱地址 | 自动填写 |
| H | 是否开票 | 人工维护 |
| I | 发票是否发送 | 人工维护 |

程序不会主动覆盖中外运的 E/G/H 或云天化的 F/H/I，并会尽量保留原工作簿中的格式、公式、列宽、合并单元格、冻结窗格、打印设置以及已有人工数据。

每一封具有独立 Message-ID / UID / 正文身份的邮件都对应独立的 Excel 行。企业名称、信用代码、金额、日期和邮箱只用于核对已有历史行，不再用来判断两封邮件是同一条申请；因此业务字段完全相同的多封邮件也会按行号从小到大一对一分配。

## 数据安全与去重

SQLite 作为本地事实记录层。系统综合 Message-ID、邮箱账户、邮件文件夹、UIDVALIDITY、IMAP UID 和内容 fallback hash 判断邮件是否已经处理，同时兼容旧版本数据库中的历史去重记录，包括旧记录没有邮箱身份信息的升级场景。

在程序重启、邮件重复扫描、UIDVALIDITY 变化、IMAP UID 变化或 Excel 暂时被占用等情况下，程序会尽量避免同一封邮件被重复写入 Excel。SQLite 会为“规范化工作簿路径 + 工作表”的目标保存行所有权，同一目标下的行由唯一索引保护；不同工作簿即使行号相同也互不冲突。

## Excel 写入恢复

Excel 写入使用同目录临时文件，并在校验后替换目标文件，以降低直接写入过程中损坏原文件的风险。

如果 Excel 文件正在被其他程序占用，邮件记录会先保存在 SQLite 中并进入等待写入状态，Excel 释放后可自动或手动重新尝试。

程序还会记录计划写入行。异常退出后重新启动时：

- 原计划行为空时继续使用；
- 已经成功写入时识别原记录；
- 原计划行被人工占用时重新选择安全位置；
- 不覆盖人工维护的 E/G/H 列。

启动、保存设置和进入邮件写入流程前会执行一次可重复的历史核对。旧数据库中没有目标标识的映射会按记录 ID 从早到晚一对一认领现有匹配行；例如登记表已经有连续的 5997、5998、5999 行时，只更新 SQLite 映射，不会再追加重复行。缺少的行才会安全追加。核对或写入前会把 `invoice-mail.db` 和原工作簿保存到：

```text
%LOCALAPPDATA%\InvoiceMailAssistant\backups\<yyyyMMdd-HHmmss>\
```

备份失败、登记表被占用、人工数据冲突或写后校验失败时，记录会保留在“等待处理”中并显示原因，不会显示为虚假的成功状态。

## 历史邮件补扫

首次配置新的邮箱账户时，程序默认从当前时间开始监听，不会自动扫描全部历史邮件。

需要补录旧数据时，可手动补扫最近 2 天。历史补扫继续经过与实时监听相同的 SQLite 去重流程，不会因为重复扫描产生重复记录。
如果 SQLite 是新建或曾被替换，程序还会在追加前检查现有 Excel 行；多条相同业务字段的历史行会按行号一对一分配，剩余申请才追加到新行，避免把既有表格重复写入。

## 自动监听与 Windows 集成

默认检查间隔为 60 秒，可配置范围为 30–300 秒。

当前支持：

- 手动立即检查；
- 暂停 / 继续自动监听；
- 邮箱连接检测；
- IMAP 会话异常时自动释放旧连接并重连一次，连续失败后进入退避，避免反复登录；
- 等待写入记录重试；
- 失败记录重新解析；
- 系统托盘；
- 关闭窗口后最小化到托盘；
- 单实例运行；
- 第二次启动时激活已经运行的窗口；
- 开机启动；
- 新开票申请提示。

## 界面

当前包含概览、处理记录、等待处理和设置页面。概览会分别显示中外运、云天化的今日收到、今日录入、等待和失败统计；托盘通知会按来源显示本次新增数量。三个表格均支持表头拖动调整列宽、横向滚动和行/列虚拟化；列宽会防抖保存并在重启后恢复到：

```text
%LOCALAPPDATA%\InvoiceMailAssistant\ui-layout.json
```

该文件只保存页面列宽，不包含邮箱、密码、工作簿内容或设置页尚未确认的修改。设置页可配置腾讯企业邮箱账号、登录凭据、IMAP 地址与端口、Excel 文件、中外运/云天化工作表名称、自动检查间隔、开机启动和历史邮件补扫。

## 构建与测试

需要 Windows 和 .NET 8 SDK。

```powershell
dotnet restore
dotnet build .\InvoiceMailAssistant.App\InvoiceMailAssistant.App.csproj -c Release
dotnet test .\InvoiceMailAssistant.Tests\InvoiceMailAssistant.Tests.csproj -c Release
```

自动化测试覆盖中外运/云天化来源分类、HTML / `mailto:`、金额与日期、严格发件人检查、Message-ID、UID / UIDVALIDITY、fallback hash、按来源统计、旧数据库升级兼容、SQLite UNIQUE 并发冲突、Excel 目标行所有权、相同业务字段的多邮件一对一分配、历史映射核对与备份、邮箱重连与退避、200+ 积压邮件、两种工作表布局写入、人工列保护、计划行恢复、人工占用行重新规划、跨年日期、列宽保存/限制以及真实工作簿结构兼容性检查。

真实业务工作簿测试应始终使用隔离副本，不应直接修改原始业务文件。README 不固定写死测试数量，实际结果以当前分支执行 `dotnet test` 的输出为准。

## Windows 10 LTSC 部署

项目声明的最低 Windows 平台版本为 `10.0.17763.0`（Windows 10 1809，适用于 LTSC 2019 及更高的 Windows 10 LTSC / Enterprise 环境），发布目标为 `win-x64`。当前构建配置没有把 Windows 10 LTSC 2016（1607）列为已验证目标，发布目标机应先确认系统版本不低于 1809。建议在构建机执行：

```powershell
dotnet publish .\InvoiceMailAssistant.App\InvoiceMailAssistant.App.csproj -c Release -p:PublishProfile=win10-ltsc-x64
```

发布结果位于 `publish\win10-ltsc-x64\`，需要将整个目录复制到目标机后运行 `InvoiceMailAssistant.App.exe`，不要只复制 EXE。该配置是自包含发布，目标机不需要另外安装 .NET Desktop Runtime；程序数据仍保存在当前用户的 `%LOCALAPPDATA%\InvoiceMailAssistant`，不应放进发布目录或随安装包复制真实业务数据。

当前代码仍以 .NET 8 为目标。若部署周期超过 .NET 8 的支持期限，应在升级到后续 LTS 版本后重新验证 Windows 10 LTSC、MailKit、SQLite、DPAPI 和真实工作簿兼容性，不应只替换运行时文件。

## 当前状态

当前版本已经完成主要业务链路：

```text
腾讯企业邮箱
        ↓
目标邮件识别
        ↓
正文解析
        ↓
SQLite 持久化 / 去重
        ↓
Excel 安全写入
        ↓
失败恢复 / 重试
```

但在正式长期无人值守部署前，仍建议完成真实企业邮箱长期连接测试、实际网络断开 / 恢复测试、长时间运行观察、SQLite 自动备份、完整结构化日志与日志轮换、处理记录搜索 / 筛选 / 详情功能以及 Windows 安装包。

因此当前版本仍不应直接宣称为 Production Ready。

## 隐私与安全

本程序在本地处理邮箱和开票数据。请勿向 Git 仓库提交企业邮箱密码或客户端专用密码、SQLite 数据库、`settings.json`、真实开票登记表、企业业务数据或含敏感信息的日志。公开仓库中的测试数据应使用虚构或脱敏内容。
